# gmaps_sweep_browser

Google Maps corridor sweep for Yogyakarta/Sleman/Bantul using browser automation.

## Overview

Sweeps ALL business categories across 119 corridors using the same browser automation approach that previously collected 24k non-unique / 3,600 unique businesses.

**Key difference from previous run**: This sweep uses ~70 query terms (all categories) instead of just 7 target categories.

## Phases

### Phase 0: Corridor Mapping (MANDATORY FIRST)
```bash
python -m src.phase0_corridor_map
```
- Loads 119 corridors from `gmaps_road_results_all.jsonl`
- Fetches road geometry from OSM Overpass
- Generates sampling points every 300m + baseline venues within 400m
- Outputs: `corridors.geojson`, `sampling_points.jsonl`, `corridor_point_counts.csv`
- **GATE: Review point counts and approve**

### Phase 1: Query Catalog & Pilot Selection
```bash
python -m src.phase1_query_design
```
- Loads 70 queries from `query_catalog.json`
- Auto-selects 3 pilot corridors (densest in Tier 1/2/3)
- Outputs: `pilot_selection.json`
- **GATE: Review pilot corridors and approve**

### Phase 2: Pilot Execution
```bash
python -m src.phase2_pilot
```
- Runs ALL 70 queries on 3 pilot corridors
- Tracks saturation curve (stops when 10 queries add 0 new venues)
- Analyzes query productivity
- Outputs: `pilot_report.json` with recommended production query list (~20-30 queries)
- **GATE: Review pilot report and approve production query list**

### Phase 3: Production Sweep
```bash
python -m src.phase3_production
```
- Runs approved queries on all 119 corridors
- Detects truncation (repeated 20/52/60/65 result counts)
- Re-runs truncated searches with denser points
- Deduplicates against baseline (50m) and internally (15m)
- Outputs: 4 final files

## Configuration

Edit `config/browser_config.yaml`:
```yaml
BROWSER_SESSION: "gmaps_sweep"
MAX_CONCURRENT_SESSIONS: 3
SCROLL_ROUNDS: 20
SCROLL_WAIT: 1.5
MIN_DELAY_BETWEEN_SEARCHES: 5
MAX_DELAY_BETWEEN_SEARCHES: 10
SAMPLING_INTERVAL_M: 300
BASELINE_BUFFER_M: 400
DEDUP_RADIUS_M: 15
```

## Limitations

- No Apify - uses browser automation only
- Saturation measured only in pilot (3 corridors)
- Truncation detection is heuristic-based
- CAPTCHA handling: stops and logs, manual intervention needed
- Rate limited by browser delays (5-10s between searches)
